# Pit Props Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add decorative mine support timbers ("pit props") to ~15% of rock walls, plus a wood-splinter debris burst when a propped wall is destroyed by an explosion.

**Architecture:** Purely client-side presentation. Props are a deterministic seeded function of tile `(x,y)` drawn as an overlay in `WorldRenderer._Draw` (same pattern as the embedded-skeleton pass). A shared `WorldRenderer.HasPitProp(x,y)` static lets `MatchClient`'s blast loop emit wood splinters over exactly the walls that look propped. Debris reuses the `ParticleSystem` pool. No Core / sim / snapshot / netcode / fog changes.

**Tech Stack:** Godot 4.6 / C# / .NET 10; Godot `game/` presentation layer; PixelLab for the sprite.

## Global Constraints

- Client-side only. No sim / `MinerSnapshot` / `TileChange` / codec / netcode / `Fog` / Core changes.
- Props are a pure deterministic function of `(x,y)` — no networking; every client draws identical props.
- Props appear ONLY on plain `TileType.Rock` tiles (skip GoldRock/CrystalRock/LavaVent/Cracked/Crumbling/Plank/non-walls).
- All new tuning values are named constants.
- No new unit tests (cosmetic; `ParticleSystem` already covered). Existing Core suite stays green (825/825).
- Build via `dotnet build Miner49er.sln -v quiet -clp:ErrorsOnly`. Launch the game via **PowerShell only** (`godot --path .`), never the Bash shim.
- Stage commits by explicit path. Commit messages end with `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`. Design docs/plans under `docs/superpowers/` stay untracked. The `.import` sidecar for the NEW sprite IS committed (it's a real new asset, not LF-churn on an existing one).

- [ ] **Step 3: Add the seed helper + tuning constant**

Add near the other private consts (top of class). Distinct salt from the skeleton pass (`0xCAFEu`) so props and skeletons don't correlate. `38/256 ≈ 14.8%`:

```csharp
private const uint PitPropSalt = 0xB0A5u;
private const uint PitPropThreshold = 38; // out of 256 → ≈15% of rock walls

// Deterministic per-tile: does this rock wall carry a pit prop? Shared by the
// draw pass and MatchClient's blast-debris check so the wall you SEE propped is
// exactly the wall that splinters. Caller is responsible for the tile being Rock.
public static bool HasPitProp(int x, int y)
{
    uint h = (uint)(x * 2246822519u ^ y * 3266489917u ^ PitPropSalt);
    return (h & 0xFFu) < PitPropThreshold;
}
```

- [ ] **Step 4: Add the prop overlay pass in `_Draw`**

Immediately AFTER the skeletal-remains `foreach` block (ends ~line 1000-something, right before the next section). Uses the same `VisibleTiles` range variables already in scope:

```csharp
// Pit props — mine support timbers embedded on ~15% of rock walls (seeded, stable per tile).
foreach (var p in VisibleTiles(vx0, vx1, vy0, vy1))
{
    if (grid.Get(p) != TileType.Rock) continue;
    if (!HasPitProp(p.X, p.Y)) continue;
    uint h = (uint)(p.X * 2246822519u ^ p.Y * 3266489917u ^ PitPropSalt);
    bool flip = ((h >> 8) & 1u) == 1u;
    var r = new Rect2(p.X * ts, p.Y * ts, ts, ts);
    if (_pitPropTex != null)
    {
        var dr = flip ? new Rect2(r.Position.X + ts, r.Position.Y, -ts, ts) : r;
        DrawTextureRect(_pitPropTex, dr, false);
    }
    else
    {
        // Procedural fallback: two vertical timber posts + a horizontal cap beam.
        float x0 = p.X * ts, y0 = p.Y * ts;
        var timber = new Color(0.40f, 0.27f, 0.14f, 0.95f);
        var cap    = new Color(0.46f, 0.31f, 0.16f, 0.95f);
        float postW = ts * 0.12f;
        DrawRect(new Rect2(x0 + ts * 0.14f, y0 + ts * 0.18f, postW, ts * 0.70f), timber); // left post
        DrawRect(new Rect2(x0 + ts * 0.74f, y0 + ts * 0.18f, postW, ts * 0.70f), timber); // right post
        DrawRect(new Rect2(x0 + ts * 0.12f, y0 + ts * 0.14f, ts * 0.76f, ts * 0.12f), cap); // cap beam
    }
}
```

- [ ] **Step 5: Add the wood-splinter emitter**

Beside `EmitExplosionDebris` (~line 400). Elongated tan/brown particles, outward-and-up with gravity, larger `Size` than dust so they read as splinters:

```csharp
public void EmitWoodSplinters(Vector2 pos)
{
    for (int i = 0; i < 8; i++)
    {
        float ang = _fxRng.NextSingle() * Mathf.Tau;
        float spd = 45f + _fxRng.NextSingle() * 85f;
        float shade = 0.32f + _fxRng.NextSingle() * 0.22f;
        Spawn(pos.X, pos.Y,
              Mathf.Cos(ang) * spd, Mathf.Sin(ang) * spd - 40f,
              200f, 0.45f + _fxRng.NextSingle() * 0.35f, 2.6f,
              new Color(0.30f + shade, 0.20f + shade * 0.7f, 0.10f + shade * 0.4f, 1f));
    }
}
```
