# Portal Gates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add colour-coded teleport gates to Expedition floors 12+ — stable (reusable two-way), unstable (one-trip then collapse), shown as a black "void" until a buried partner is uncovered.

**Architecture:** Portals live in the engine-free `Miner49er.Core` sim as a paired list (mirroring the `LavaVent`/`MoldPatch` pattern). Placement is deterministic in `MapGenerator`, so the host AND every client generate identical portals from the seed — therefore portal positions/kinds/links are NEVER sent over the wire. Only the one-shot teleport event rides the snapshot (a transient list, exactly like the recent bot-whistle work) to drive SFX and client-side collapse tracking. Teleport is host-authoritative inside `Simulation.TryMove`.

**Tech Stack:** C# / .NET 10, Godot 4.6 (`game/`), xUnit (`Miner49er.Core.Tests`). PixelLab for the archway sprite.

## Global Constraints

- Engine-free `Miner49er.Core` stays deterministic and Godot-free. All randomness comes from `config.Seed` / process-stable `MapConfig.FloorHash`, so host and clients agree.
- Snapshot codec is append-only and positional: Write order MUST exactly match Read order. New fields append AFTER `Whistles` (the current last field). `StunRemaining`/`PendingFalls` remain non-serialized — do not add fields to the wire beyond what this plan specifies.
- Portals are Expedition-only, floors ≥ 12, on a deterministic ~1-in-4 roll; 1–2 pairs per gated floor. No effect on the escape tile, artifact/treasure gate, gold, or scoring.
- Only miners (human + AI bot) teleport; monsters and thrown objects never trigger a gate.
- `PortalKind` has exactly two values: `Stable`, `Unstable`. Black is a derived *state* (partner not revealed), not an enum value.
- Commit messages end with `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
- Never `git add -A`; stage only the exact files each step lists. Never stage `.superpowers/`, `*.uid`, `Temp/`, `_preview_*`.
- Build/test with `dotnet` (Bash or PowerShell). Run `godot` via PowerShell only if needed.

- [ ] **Step 9: Implement `PlacePortals` and wire it into `Generate`**

In `src/Miner49er.Core/Map/MapGenerator.cs`, add the helper (place it near `PlaceBuriedIdols`, ~line 664):

```csharp
    // Colour-coded gate pairs. Each pair shares one kind (Stable/Unstable). Each end
    // is either EXPOSED (on a Floor tile in the play region) or BURIED (in ordinary
    // Rock bordering the region, uncovered by mining). Buriedness is implicit in the
    // tile type — no grid mutation here — so the sim derives "revealed" from the grid.
    // Deterministic: ordered scan + seed-shuffle, so host and every client agree.
    private static List<PortalSpec> PlacePortals(TileGrid g, Random rng, int pairCount,
        HashSet<GridPos> region, List<GridPos> spawns, IEnumerable<GridPos> taken)
    {
        var result = new List<PortalSpec>();
        if (pairCount <= 0) return result;

        var used = new HashSet<GridPos>(taken);
        used.UnionWith(spawns);

        var floorCands = g.Positions()
            .Where(p => region.Contains(p) && g.Get(p) == TileType.Floor && !used.Contains(p))
            .ToList();
        Shuffle(floorCands, rng);

        var rockCands = g.Positions()
            .Where(p => g.Get(p) == TileType.Rock && HasRegionNeighbor(g, p, region) && !used.Contains(p))
            .ToList();
        Shuffle(rockCands, rng);

        int fi = 0, ri = 0, id = 0;

        // Pull one end: 50% exposed (Floor) / 50% buried (Rock); fall back to the
        // other pool if one is exhausted, so a pair always gets two distinct tiles.
        GridPos? NextEnd()
        {
            bool wantBuried = rng.Next(2) == 0;
            if (wantBuried && ri < rockCands.Count) { var p = rockCands[ri++]; used.Add(p); return p; }
            if (fi < floorCands.Count)              { var p = floorCands[fi++]; used.Add(p); return p; }
            if (ri < rockCands.Count)               { var p = rockCands[ri++]; used.Add(p); return p; }
            return null;
        }

        for (int pair = 0; pair < pairCount; pair++)
        {
            var a = NextEnd(); var b = NextEnd();
            if (a is null || b is null) break;      // ran out of tiles — place fewer pairs
            var kind = rng.Next(2) == 0 ? PortalKind.Stable : PortalKind.Unstable;
            result.Add(new PortalSpec(id, a.Value, kind, id + 1));
            result.Add(new PortalSpec(id + 1, b.Value, kind, id));
            id += 2;
        }
        return result;
    }
```

```csharp
        // Placed before the arrival hazard checks so those evaluate at the DESTINATION.
        // Sequential per-miner processing gives "lowest id wins" on an unstable gate for
        // free: the first mover collapses it, later movers find it collapsed → no-op.
        var enteredPortal = _portals.FirstOrDefault(p => p.Pos == target);

            enteredPortal.CooldownRemaining = Config.PortalCooldownSeconds;
            link.CooldownRemaining = Config.PortalCooldownSeconds;

                enteredPortal.Collapsed = true;
                link.Collapsed = true;
            }
            _events.Add(new PortalUsed(id, target, link.Pos, enteredPortal.Kind));
            m.Pos = link.Pos;
            target = link.Pos;   // the client snaps on the non-adjacent position jump
        }
```

## Notes for the implementer

- **Codec symmetry is load-bearing.** `PortalUses` must be written and read in the same position (after `Whistles`, before `TileChanges`). Task 3 Step 6 (full suite) is the guard.
- **Determinism:** never introduce non-seeded randomness into placement. The `NextEnd()` helper draws only from `rng`.
- **Cosmetic-desync tradeoff (accepted):** a client that misses the one snapshot carrying an unstable `PortalUse` will keep rendering that gate as alive. It is harmless — the host refuses the teleport (gate is `Collapsed` server-side), so it is visual only. This matches the project's earlier decision to drop cheat-resistant fog culling. If this proves annoying in playtest, escalate to add a tiny persistent collapsed-id list to the snapshot.
- **Bots:** no bot-specific work is required — bots move through `TryMove`, so they teleport on stable gates automatically. The optional "Miner+ bots avoid red gates" enhancement from the spec is intentionally deferred.
